# KPI-DRIVE Kanban Test Task

Flutter Web приложение для тестового задания KPI-DRIVE.

Приложение:
- получает задачи из API KPI-DRIVE;
- показывает задачи на Kanban-доске;
- поддерживает drag-and-drop;
- сохраняет `parent_id` и `order` на backend.

## Что реализовано

- загрузка задач из backend KPI-DRIVE;
- группировка задач по `parent_id`;
- сортировка задач по `order`;
- drag-and-drop внутри колонки;
- drag-and-drop между колонками;
- сохранение `parent_id` и `order` на backend;
- rollback при ошибке сохранения;
- loading / error / empty states;
- защита от повторных действий во время сохранения;
- тёмный UI в стиле KPI-DRIVE.

## Запуск

Основная команда:

```powershell
.\scripts\run_web_dev.ps1
```

Перед запуском нужен файл `.env.local`.

`.env.local` не коммитится. Пример лежит в `.env.example`.

Формат `.env.local`:

```env
KPI_DRIVE_TOKEN=your_token_here
```

## Почему используется local proxy

Flutter Web не может напрямую обращаться к KPI-DRIVE API из браузера из-за CORS-ограничений. Поэтому проект использует локальный proxy, который проксирует запросы к KPI-DRIVE API.

Это не mock. Приложение работает с реальными данными backend KPI-DRIVE.

## Проверка

1. Запустить `.\scripts\run_web_dev.ps1`
2. Дождаться загрузки задач
3. Перетащить задачу внутри колонки
4. Перетащить задачу в другую колонку
5. Дождаться статуса сохранения
6. Обновить страницу и проверить, что изменения сохранились

## Видео

Короткий план видео 1–3 минуты:

1. Запуск проекта
2. Загрузка реальных задач
3. Drag внутри колонки
4. Drag между колонками
5. Сохранение изменений
6. Обновление страницы

## Безопасность

- `.env.local` не коммитится;
- bearer token не хранится в публичном коде;
- в репозитории находится только `.env.example`.
